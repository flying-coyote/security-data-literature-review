## Sensitivity notes (where a companion edit or an owner call changes a number)

- **CH-vs-ES tier (drives H3-PERF 19 vs 21).** The bibliography block ("ClickHouse vs Elasticsearch - Storage Efficiency", ~line 1858) is still tiered `A (Benchmark study)`, which contradicts the repo's own treatment everywhere else: Appendix A places vendor benchmarks at B, the manuscript's §3.2.2 and Table 4 both call it "a vendor benchmark", the recommended book language says "treat that as a vendor figure", and the canonical bundle's 2026-07-11 note tiers it B. The apply step re-tiers the entry to B first (edit 1 below); 19/25 is the rescored value.
- **CIDR probe as an H3-PERF leg (drives 19 vs 17, High either way).** §3.2.2 cites the first-party CIDR probe with full provenance (`lab/cidr_probe.py`, 2026-06-07, 20M rows, single host), so it is a scoreable leg under rubric §1, but it has no bibliography block yet; edit 2 catalogues it, following the S3-derivation block precedent. If the owner rules it out instead, H3-PERF is 3 legs → 17/25 (3/3/3/5/3), still High.
- **H-STREAM-01 restoration path.** The demotion is entirely the source-count anchor. One additional verified, catalogued production or peer-reviewed leg cited in §3.2.3 (a real Kafka Streams deployment source would also repair the section title's Samza-vs-Kafka-Streams tension) lifts count 1→3 pts and returns the hypothesis to 17/25 High. Nothing in this rescore blocks that; it just can't be assumed before it exists.
